# Next-agent operating brief

You are continuing EvidenceSpace after product and design approval. Preserve the same mindset:

- pursue exceptional product-specific quality, not imitation;
- refine the approved 37-screen system instead of inventing a replacement shell;
- simplify copy and hierarchy, not capability;
- make underused space meaningful without filler cards;
- use familiar human language and restrained typography;
- use only causal, purposeful, performant motion with reduced-motion behavior;
- connect surfaces through canonical objects and backlinks;
- make the app useful for a solo user and stronger with an authorized team;
- remain calm, skeptical, and source-backed;
- surface contrary material and uncertainty;
- keep AI proposed until an authorized person approves;
- separate membership, case access, object visibility, payment, and lawyer sharing;
- preserve original bytes and derivative lineage;
- make recovery a first-class user experience; and
- keep canonical docs and handoff current with every material change.

## Human-interface acceptance check

A technically correct screen is not acceptable if it reads or looks machine-generated.

- Use the words a real user would use. Keep legal precision where it protects meaning, but remove internal jargon, policy language, and AI terminology that the user does not need.
- Give every sentence a job. Remove duplicated status, instructions for obvious controls, and explanatory copy that compensates for weak hierarchy.
- Shorten before shrinking. Do not make excessive copy tiny to force it into the composition.
- Use headings to orient the user, not to advertise the product. Routine work belongs above oversized display type.
- Create appeal through proportion, spacing, alignment, typography, meaningful content, and complete states—not filler cards, generated imagery, excessive glass, arbitrary gradients, or ornamental AI motifs.
- Use motion only to explain cause, object movement, continuity, progress, or status. Keep it brief and provide reduced-motion behavior.
- Read visible copy aloud and inspect the screen at delivery size. The user should quickly know where they are, what matters, and what the primary action will do.
- Reject polished work that no longer looks like EvidenceSpace.

## Do not

Do not restart discovery, copy another productivity app, create a generic dashboard, change the approved palette/background without evidence, add AI-generated decoration, use animation everywhere, write large promotional headings, over-explain ordinary controls, convert Story Field back to generic chat, merge every function onto one page, collapse Evidence and Research, hide Work in Room, make AI an eighth case lens, use platform emoji as core icons, merge stale branches wholesale, claim unrun checks, or start the marketing site.

## First action on a UI task

1. Open the exact approved prototype screenshot.
2. Name what remains unchanged.
3. Identify the real defect or underused area.
4. Define the smallest useful improvement and all relevant states.
5. Draft the shortest familiar copy that preserves the required meaning.
6. Implement with source-linked synthetic data and clear route ownership.
7. Inspect beside the source at supported window/theme/accessibility states.
8. Read visible copy aloud and remove anything repetitive, oversized, or unnecessary.
9. Reject the change internally if it no longer looks like EvidenceSpace.

## First active slice

Global Home, Cases, Case C-03 Brief, Evidence E-04, and Context Lens continuity. Do not scale to all routes until this direction is recognizable and reviewed.

## Completion standard

A screen render is not completion. The user outcome must work end to end in its supported scope with permissions, provenance, states, failure/recovery, accessibility, tests/evaluations, privacy-safe telemetry, documentation, migration/rollback, remote diff inspection, exact-head CI, and honest unverified areas.

Routine branch, PR, and merge operations are authorized. That is not permission to bypass quality, fabricate evidence, expose private data, or merge rejected/temporary work.
