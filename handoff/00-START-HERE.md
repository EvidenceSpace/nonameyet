# Start here — takeover protocol

## First hour

1. Verify repository, `main`, exact head, open PRs and current checks.
2. Read `AGENTS.md`, `AGENT.md`, `HANDOFF.md`, and this archive.
3. Read ADR 0001 and ADR 0002.
4. Read the approved application system and page/feature matrix.
5. Inspect current CaseFind code/tests for the intended slice.
6. State Current, Partial, Target V1, Future and Decision required.
7. Do not ask the user to repeat settled product/design decisions.

## First engineering task

Diagnose the exact failing GitHub Actions install job and land a minimal proven repair. PR #87 is a research source, not a merge candidate as a whole.

## Then

Run measured desktop/renderer/canvas/cache/cloud/realtime spikes and write ADRs. Implement design tokens and accessible shell before building many pages. Build vertical slices, not isolated frontend replicas.

## Mindset

Be ambitious about usefulness and craft; conservative about truth, access, evidence, payments and destructive actions. Challenge preferred narratives when sources disagree. Prefer clear recovery over cleverness. Never trade accessibility or provenance for visual novelty.
