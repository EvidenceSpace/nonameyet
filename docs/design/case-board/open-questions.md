# Open questions and risks

## Decisions required

1. **Weighing model.** Is "party once, independent double, objective most" acceptable as a visible thinking aid? Who reviews it (a practising lawyer)? How is it explained in the UI?
2. **Legal elements and deadlines per case type and jurisdiction.** Need qualified review before release. Wrong deadlines are the biggest trust risk.
3. **Room calls.** Native calls vs external link first; recording and transcripts (consent, storage, privilege).
4. **Light mode vs board as the default** for small cases.
5. **PR #124 whiteboard.** Keep it as the drawing layer underneath the case board, or replace it? It stays unmerged until the owner decides.
6. **Board engine** (from the earlier direction): custom vs a library such as tldraw (commercial licence) or React Flow.

## Risks

- Lawyers won't do duplicate work. We need excellent export and a handover pack.
- Self-represented users may never reach the board. Light mode and next step must carry them.
- Day-one overwhelm. Show half-empty and calm, one next step.
- AI extraction errors. Confirm before use, with source links everywhere.
- Over-precision. Measurements and sightlines can look like proof; label them as estimates and checks.

## Unknowns to test

- Will people confirm suggestions consistently if each confirmation shows a visible change?
- Which outputs do people actually pay for (letters, bundles, lawyer handover)?
- Are five or six building blocks enough for most cases? Test against real situations from the owner's circle.
